# 离线验证与预留接口

当前决定：模型接入暂缓，接口保持空白。没有调用外部模型，没有读取或使用现有密钥。

## 现在可以使用

双击桌面项目内的 `检查占位数据.command`，检查既有示例是否符合结构要求。它只展示手工占位结果，不会根据新文字生成蜂群，也不会联网。

`nesting.py` 提供输入校验、JSON 结构校验、事件 ID 对齐、数值范围检查，以及预留的模型接口。使用 Python 3 标准库，无需安装额外依赖。

`test_nesting.py` 检查错误格式、参数越界、重复字段、事件乱序、重试与失败处理。网络结果均由测试模拟，不能据此声称真实模型效果或性能已经验证。

## 日后接入

暂不填写 `NESTING_ENDPOINT`、`NESTING_MODEL`、`NESTING_API_KEY`。接口采用 Chat Completions 消息格式；实际供应商兼容性需接入时验证。完整请求地址、模型名和密钥只从运行环境读取，不硬编码。

接口格式参考：[OpenAI 官方 Chat API 文档](https://developers.openai.com/api/reference/resources/chat)。本版本把 schema 放在系统提示词中，并在返回后本地校验；尚未依赖供应商的结构化输出功能。

接入后的流程：输入两段话 → 最多 8 秒总等待 → 校验模型输出 → 交付 output 字段给动画。仅格式不合格时在剩余时限内重试一次；网络错误直接结束。不用占位数据冒充成功结果。

默认不保存输入或模型响应。明确使用 --save 才会保存结果及提示词指纹；保存文件已有时停止，避免覆盖。保存结果可能包含模型引用的原话，现场版本应另行落实清理机制。

## 开发者运行入口

在本目录运行：

```sh
python3 nesting.py demo
python3 -m unittest -v test_nesting.py
```

自定义输出只做结构验证：

```sh
python3 nesting.py validate --input 输入文件.json --candidate 模型输出.json
```

日后配置环境变量后才使用 `python3 nesting.py live`。这一入口尚未经过真实服务验证。
